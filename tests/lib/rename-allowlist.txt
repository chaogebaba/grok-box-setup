# rename-allowlist.txt — N3/N5 of the 5.10.0 rename (blueprint
# fleet2-rename-grokfleet). Checked by tests/test-rename-allowlist.sh.
#
# FORMAT, one entry per line, TAB-separated:
#
#     <tracked path><TAB><extended regex><TAB><number of matching LINES>
#
# NEVER a bare path (r2-B6): a whole-file exemption would make the very test
# that enforces the rename blind to new mentions. Two properties follow from the
# count. A mention that APPEARS in an allowlisted file fails, because the count
# moves. A mention that DISAPPEARS fails too — which matters here, because most
# of these lines are a compatibility surface that must survive 5.10.0 intact.
#
# Each entry is counted INDEPENDENTLY (`grep -cE`), so a file may carry several
# entries whose line sets overlap: a broad `fleet2` count for the file plus a
# narrow one for a specific mention. That overlap is the point (r4-n2). The soak
# marker gets its own path-only pattern in every file that names it, so renaming
# the marker fails on that entry even if the file's overall count happens to
# stay put — a single blanket count would hide exactly that.
#
# WHY EACH GROUP STAYS
#   fleet2-state-store / fleet2-zero-touch-join / fleet2-release-install /
#   fleet2-rename-grokfleet / fleet2-lease-api
#       Blueprint FILENAMES cited from comments. Those documents exist under
#       those names; a "corrected" citation would be a wrong citation.
#   /var/lib/grok-fleet/fleet2.soak-ok
#       r3-n1. State under $FLEET_STATE that gates flipping apply=true.
#       Renaming it would silently reset an in-flight soak.
#   FLEET2_*
#       The pre-rename env spellings are GONE as of 5.11.0. What is left names
#       them only to prove they are ignored (tests/test-install-vps.sh) or to
#       record that they were (a comment in vps/install-vps.sh).
#   fleet2.conf / the residual `fleet2`
#       The REMOVAL of the compatibility surface: `STALE_CLI="fleet2"` and the
#       guards that delete `/usr/local/bin/fleet2` and the obsolete phase-2
#       drop-in by their historical names, plus the tests that seed a 5.10.0
#       host and assert every one of them is gone afterwards. Naming a thing in
#       order to delete it is not a compatibility surface.
#   tmp/orch/*
#       Historical records — dispatch logs and gate memos, never edited.
#
# 5.11.0 DELETED the compatibility layer, and this file shrank with it. What
# remains is the soak marker, the blueprint filenames, and the code and tests
# that REMOVE the retired names. The next thing to go is `STALE_*` itself, once
# no host can still be carrying a 5.10.0 unit link.
